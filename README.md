# EMOVE Profe

**Free Erasmus+ training and classroom resources for European teachers, by [eMove Academy](https://www.emoveacademy.com).**

A public website plus an installable web app (PWA). Teachers request access, the super-admin approves each account, and approved teachers can:

- **Learn**: the interactive microcourse *Erasmus+ from scratch* (5 units, 7 activity types, final quiz, printable certificate, glossary) and a hub for each eMove course: overview, the full day-by-day syllabus (mark each day as studied), resources connected to each day and the course's discussion space.
- **Resources**: a library of classroom activities, routines and templates organised by the seven eMove pathways and linked to the eMove courses, with filters, favourites and print/PDF.
- **Community**: discussion spaces (staff room, Erasmus+ help desk, find a partner, classroom ideas and one per eMove course), the latest activity, and an opt-in teacher directory to find colleagues and project partners.
- **Profile**: progress, certificates, notes, personal details, password and the community profile (appear in the directory, show email, presentation, what you are looking for, courses you are interested in).

The **super-admin** (Admin tab) moderates the community (pins and deletes any discussion or message), approves or rejects requests, resets passwords, deletes accounts, sees each teacher's progress and which eMove courses they opened, and exports the list to CSV.

The platform is in English; the public website is in English and Spanish with a language switch. All access is free; there are no payments.

## Structure

```
src/
  data-emove.js      eMove pathways, courses, stages, countries
  data-course.js     the microcourse (units and activities), quiz and glossary
  data-resources.js  the resource library and the eMove course (and day) each resource connects to
  data-syllabus.js   the syllabus of every eMove course (generated by tools/syllabus/build.py)
  core.js            helpers, icons, brand mark, state, shell and router
  accounts.js        sign in, request access, sync between devices, super-admin panel
  academy.js         course map, lesson player, activity types, quiz, certificate, glossary
  pages.js           home, resources, profile
  learn.js           Learn: the microcourse card and the hub of each eMove course
  community.js       discussion spaces, threads and the teacher directory
  styles.css         visual system (eMove colours, Inter)
web/
  website.py         public website: one interactive landing page in English and Spanish
  guides.py          the Erasmus+ guides (English and Spanish)
  web.css            styles of the public website
netlify/functions/
  api.mjs            accounts and community API (Netlify Functions + Netlify Blobs)
public/              icons, eMove logo and service worker
tools/               data export for the website, a local dev server and the syllabus generator
build.py             builds everything into dist/
```

Adding content means editing the `data-*.js` files: a new unit or activity in `COURSES`, a new resource in `RESOURCES` (and its course in `RES_COURSE`). No other code needs to change.

The syllabus comes from the programmes eMove publishes at `emoveacademy.com/course-content/<course>.txt`. When eMove updates one, save the new file in `tools/syllabus/` and run `python3 tools/syllabus/build.py`.

## Run it locally

```
python3 build.py
ADMIN_EMAILS=you@example.com node tools/dev.mjs     # http://localhost:8888
```

The dev server keeps accounts in `.store/`. Request access with the email in `ADMIN_EMAILS`: that account is approved automatically and sees the Admin tab.

## Publish on Netlify

1. Netlify → Add new site → Import from GitHub → choose this repository. Build settings come from `netlify.toml`.
2. Site settings → Environment variables:
   - `ADMIN_EMAILS`: the super-admin email (several separated by commas).
   - `AUTH_SECRET`: a random text of at least 32 characters.
3. Deploy. The website is at `/`, the platform at `/app/`.

Environment variables only reach the accounts API after a new deploy: after changing them, push a commit or use *Deploys → Trigger deploy*.
